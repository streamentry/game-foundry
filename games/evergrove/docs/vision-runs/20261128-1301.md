**Idea 1 result.** The first generator, written to the proposal, accepted any board that was unique *with* the axle. The implementer measured 0 of 60 boards that needed the axle. Random fork trees are almost always unique from tile shapes alone: 57 of 3,272 trees with at least three forks (1.7%) have two or more answers. So the proposal's acceptance rule could never show what the link adds. The coordinator changed the generator. It now keeps only trees that are ambiguous without the axle, then tries up to 60 non-adjacent pairs of four-orientation tiles for an axle that leaves exactly one answer. It uses up to 2,000 attempts per seed. Seeds 0–59 then gave 60 boards, all needing the axle. Link-aware deduction (neighbour arc consistency plus axle pruning) solves 47 with no guess; 13 need a guess, at most 4. The test locks these numbers, and the true answer survives deduction on every board. For the first time in these runs, a rule makes reasoning jump across the board. The cost: only about 2% of random trees qualify, so these boards would have to be built ahead of time and reviewed, not generated live.

**Idea 2 review fixes.** The implementer's basket line was "More quince tree, planted from your basket…". It breaks for plural catalogue names ("More poppies" works, "More quince tree" doesn't). It now reads "Planted from your basket. It came from the quince tree you chose after stream 3." Both new captions now return "" outside Living mode, matching `ThingStory.For`, so the puzzle-matched control never shows village memories.

**Ideas 3 and 5 review fix.** The implementer added three lines to `TreePlay.cs`, which broke the existing line-count guard (`PuzzleChainTests.ViewFilesDidNotGrow`, 1,099 lines). The pulse moved into `TreePlay.Turns.cs` (`OpenTurn`), and so did the spoken hint, now called from `SpeakTurn`. `TreePlay.cs` is back at 1,099 lines. The source check in `StarterTurnTests` was updated to match.

**Idea 4 finding.** Under simulation the old palette fell below its own 1.36:1 promise: sage vs rose 1.22:1 (protanopia), honey vs sky 1.25:1 (protanopia) and 1.32:1 (tritanopia), sky vs rose 1.30:1 (deuteranopia). Two colours had to move, because those pairs share no colour. Honey is now (1.00, 0.91, 0.62) and rose a dusty (0.56, 0.37, 0.40). The lowest pair is now honey vs sky under protanopia, 1.365:1. The token's icon is white (checked in `ui-neighbors.png`), so the darker rose makes it easier to see on that turn. Honey and sky still carry a white icon at low contrast, as before.
