## 1. Do forked streams need real reasoning? (puzzle depth)

- **Vision:** §2.2 "depth from a system, not content volume" (unsolved). Runs 0927 and 1001 found that local deduction alone solves every authored board and every root-stone board. Both are single paths (ends, straights, corners). Their next step: try a mechanic that breaks local forcing. The classic candidate is a **fork**: a three-way tile, so the stream becomes a branching tree that must reach every tile without loops. Whether a branch must close here or there is a global question (connectivity, no loops), not a neighbour question.
- **Player value (later):** if forks on a 5×5 board need lookahead, a "the stream splits to water two beds" mechanic earns a painted tile and a place in the chapters. If not, forks are dropped before any art.
- **Strongest counterargument:** another hidden number; and solver guesses are a proxy for human difficulty. Also forks may make the rule harder to say in one sentence.
- **Cheapest disproof:** if 5×5 fork boards are also fully forced by arc consistency with zero guesses, forks add shape but not reasoning.
- **Files:** new `Assets/Scripts/Core/ForkBoards.cs` (+ `.meta`); new `Tests/ForkBoardsTests.cs`.
- **Acceptance (pure C#):** port-mask tiles (end, straight, corner, fork) on a 5×5 grid; a board is a random spanning tree; deterministic per seed; generation keeps only boards with exactly one solution; the solver's answer is a single connected tree covering every cell with no leaks; arc-consistency deduction never removes the true orientation; deduce-then-guess search finds exactly the generated solution. Over seeds 0–99: yield, forced count and guess distribution go in the run log.
- **On screen:** nothing.

## 2. Hold a thing to hear its story (truthful village memory)

- **Vision:** §3 "the place remembers it truthfully"; charter rules 3 and 5. Holding a thing on the garden map today shows only its family's generic label ("Plant a tree"). The map forgets what each thing *is* and when it came.
- **Player value:** hold the quince on the map and read "Quince tree, chosen after stream 3. Four streams have run past it since." A true, progress-measured history, never clock time.
- **Strongest counterargument:** few players long-press; more words on a picture-first map.
- **Cheapest disproof:** in M3, ask "when did you plant that?" while the player holds a thing; if answers are no better than without the caption, revert.
- **Files:** new `Core/ThingStory.cs` (+ `.meta`); `Unity/GardenMapView.cs` (the item gets an optional caption, used by the existing `LongPressCaption.Attach`); the Unity file that fills map items for chosen things; new `Tests/ThingStoryTests.cs`.
- **Acceptance:** the caption names the item from the catalogue and the stream it came from (choice index + 1), and the number of later choices as streams since ("No streams have run past it yet." / "One stream has run past it since." / "Four streams…" spelled one to twelve, digits above); only in Living mode for a chosen thing with a valid index; English only; otherwise the old generic caption is unchanged; same save gives the same words; no "days", "ago" or clock words.
- **Art/feel:** the existing caption bubble; one or two short sentences.

## 3. The table stays set (family play, one device)

- **Vision:** §1a "any hand can help", §4.4 rung 0; charter §3.5b "one phone, passed hand to hand". Take turns resets to "alone" on every new board, so a family must tap the token again each time, and the first player always starts.
- **Player value:** once a grandparent, a parent and a child set "three", the next board opens at three, and the first move goes to the next person round the table. Everyone gets to start.
- **Strongest counterargument:** a solo player who once tried take turns would see it stay on.
- **Cheapest disproof:** in the family co-play session, count how often the token is re-tapped per board without this change; if families play one board per sitting, it earns nothing.
- **Files:** `Core/TakeTurns.cs` (`StartingTurn`); `Unity/TreePlay.Turns.cs` (session memory); `Unity/TreePlay.cs` (no net line growth: it sits at its 1,099/1,100 cap); new `Tests/TableSetTests.cs`.
- **Acceptance:** `StartingTurn(boardsTogether, players)` is `boardsTogether mod players`, 0 when alone, never throws on out-of-range input. The count lives in a static field for the app session only: never saved, never in PlayerPrefs. Setting "alone" ends it. A board finished together advances the next board's starting turn by one.
- **Art/feel:** the token simply opens already wearing the right colour and pips.

## 4. Wet and dry pipes differ for every eye (art and readability)

- **Vision:** §2.7 "readable and touchable"; checklist 92 (colour-blind pass). The one colour distinction the puzzle depends on is water channel versus dry channel. Run 1001 proved each has 3:1 contrast on every tile, but not that the two differ from each other for a colour-blind player.
- **Player value:** a player with deuteranopia, protanopia or tritanopia can still tell where the water has reached.
- **Strongest counterargument:** the leak markers and the solve bloom already carry the meaning without colour.
- **Cheapest disproof:** if both channels already differ strongly in lightness, every simulation passes and nothing changes (a lock is still worth having).
- **Files:** new `Core/ColourVision.cs` (+ `.meta`, Machado 2009 full-severity matrices in linear RGB); new `Tests/ColourVisionTests.cs` reading colours from `MosseloraTheme.cs` the way `ThemeContrastTests` does.
- **Acceptance:** for normal vision and the three simulations, WaterChannel vs DryChannel has a relative-luminance contrast of at least 1.5:1; simulation of grey is grey; matrices rows sum to 1. If a pair fails, the run log records it and the smallest lightness change in the same hue is proposed, not shipped blind.

## 5. Each tile says which way it opens (accessibility)

- **Vision:** §2.7; M5 accessibility gate; checklist 93 ("VoiceOver and TalkBack finish a board"). A tile today reads "Row 2, column 3, corner, dry". It never says which way the pipe points, so a blind player can't solve the board at all.
- **Player value:** the same tile reads "Row 2, column 3, corner, dry. Opens up and right."
- **Strongest counterargument:** screen-reader players may want shorter labels; directions may change every tap and make speech noisy.
- **Cheapest disproof:** the blind-tester session already needed for checklist 93: if the tester can't use the openings to finish a 3×3 board, rethink.
- **Files:** new `Core/TileOpenings.cs` (+ `.meta`); `Unity/EvergroveApp.Layout.cs` (`TileSpeech`); new `Tests/TileOpeningsTests.cs`.
- **Acceptance:** for every kind and rotation, the words list exactly the ports `PipeRules.HasPort` reports, in the order up, right, down, left ("Opens up." / "Opens up and right." / "Opens left and right."); invalid rotations return an empty string; English only, other locales keep today's label.
