## 1. No chapter board is another one turned (puzzle depth)

**Serves:** vision §2.2 "depth from a system, not from content volume" and §0's warning that rotated variants add no difficulty.

**Player value:** if the axle chapter (`LinkedForkChapter.DrawByLevel(12, 240)`) ever goes into play, a player who solves board 3 should never meet board 3 again turned a quarter or mirrored, which would be content padding in disguise.

**Strongest counterargument:** the boards come from different seeds of a random generator, so duplicates are very unlikely and the gate may prove nothing.

**Cheapest disproof:** run the gate once. If all 12 shapes are distinct, record that and move on; the gate still guards any later redraw.

**Files:** `Assets/Scripts/Core/LinkedForkChapter.cs` (add `SameShape(int seedA, int seedB)` and `DistinctShapes(int[] seeds)`), `Tests/LinkedForkChapterTests.cs`.

**Rule:** two linked-fork boards have the same shape when one of the 8 symmetries of the square (4 rotations, each optionally mirrored) maps board A's solution masks onto board B's, with every cell's port mask transformed the same way (ports turn and mirror with the board), **and** maps A's linked pair {A, B} onto B's linked pair (as an unordered pair). Boards of different size are never the same shape. `DistinctShapes` returns how many distinct shapes are in the list (count of equivalence classes). Pure, deterministic, no clock.

**Acceptance (pure C#):**
- `SameShape(s, s)` is true for a qualifying seed.
- A hand-built check: a board compared with a copy of itself turned 90° (masks rotated, cells moved, pair moved) is the same shape; expose an internal/public helper taking `LinkedForkBoard` values so the test can build the turned copy, e.g. `SameShape(LinkedForkBoard a, LinkedForkBoard b)`.
- Mirrored copy is also the same shape. Changing one cell's mask or moving the pair makes it different.
- Record `DistinctShapes(DrawByLevel(12, 240))` and assert the measured value (expected 12). Not wired into play.

**On screen:** nothing. It is a hidden gate.

**Art/feel:** none.

## 2. "Together" only when more than one person moved (truthful village memory)

**Serves:** vision §3 "the place remembers it truthfully", §1a family play, taste charter rule 5.

**Found problem:** when the take-turns token is set to two or more, solving a thing's board saves `world.MarkTogether(thing)` (`EvergroveApp.Hub.cs`), and the thing's story then says it was solved together. `TreePlay.PlayedTogether` is only `players > 1`. If a grandparent sets the table for two and then solves the whole board alone, the garden permanently remembers something that didn't happen, and the solved moment says "Solved together, both of you."

**Player value:** "solved together" and "the three of you" in the garden are always true: they count only the seats that actually made a move.

**Strongest counterargument:** someone at the table may help by pointing without tapping; counting taps undercounts real help.

**Cheapest disproof:** in a family session, ask whether a "solved together" line ever felt wrong. Undercounting is the safe direction: the game never claims more than it saw.

**Files:** `Assets/Scripts/Core/TurnLedger.cs` (add `Movers(int step)`), `Assets/Scripts/Unity/TreePlay.cs` (`PlayedTogether`, `Players`), `Assets/Scripts/Unity/TreePlay.Turns.cs` (`TableSolved`), `Tests/TurnLedgerMoversTests.cs` (new).

**Rule:** the ledger notes `step → turn after the move` for every move that passed the turn (`NoteTurn`). `Movers(step)` = the number of distinct seats `At(k - 1)` over every noted key `k` with `1 ≤ k ≤ step`. Key 0 (the board's opening turn) is not a move. Moves undone (keys above the current step) don't count. `Clear()` forgets movers too. In Unity: `PlayedTogether` = `together && Movers(current undo steps) >= 2`; `Players` reports `Math.Min(players, movers)` when together and at least 2 moved, else 1. `TableSolved` lights and pulses only when `PlayedTogether`, and speaks `TakeTurns.SpokenSolved(Players)`.

**Acceptance (pure C#):** no moves → 0; seat 0 moves three times on a two-seat table (record at steps 1..3 with turns that pass) → counts correctly; moves by seats 0 and 1 → 2; three seats → 3; record then a lower `Record` (undo then a new move) forgets the abandoned moves; `Clear` → 0; head-start or non-noted steps never add a mover.

**On screen:** a board solved by one person while the table is set shows no "together" bloom, and the thing's story doesn't claim it was solved together. With two real movers, nothing changes.

**Art/feel:** no new art. Truth over celebration.

## 3. The table token says what a tap will do (family play, one device)

**Serves:** vision §1a "any hand can help", §4.4 rung 0 side-by-side play.

**Player value:** the take-turns token cycles alone → two → three → four → alone, but nothing says so; a grandparent has to tap and watch. Holding the token now says where the table stands and what the next tap does, e.g. "Two at the table. Tap for three." Holding is already how every control in the game explains itself.

**Strongest counterargument:** words on a hold are rarely discovered; the pips already show the count.

**Cheapest disproof:** in the family session, see whether anyone holds the token. If no one does, the line costs nothing visible.

**Files:** `Assets/Scripts/Core/TakeTurns.cs` (add `TableCaption(int players)`), `Assets/Scripts/Unity/TreePlay.cs` (`TogetherRow`: attach a live caption), `Tests/TableCaptionTests.cs` (new).

**Rule:** `TableCaption(1)` = "Playing alone. Tap to take turns with someone."; `(2)` = "Two at the table. Tap for three."; `(3)` = "Three at the table. Tap for four."; `(4)` = "Four at the table. Tap to play alone." Values ≤ 1 read as alone; above 4 read as four. The text matches `NextPlayers` exactly (the test checks this for 1..4). English only.

**On screen:** holding the token shows the caption for the current table size; it updates after each tap. Nothing else changes.

**Art/feel:** the existing hold caption style.

## 4. Seat pips grow with the text (art and readability)

**Serves:** taste charter rules 4 and 6 ("readable at 150% text"), vision §2.7.

**Player value:** the seat pips under the take-turns token are 9 px dots 12 px apart at every text size. A player who chose 125% or 150% text gets pips that grow with it, so whose turn it is reads at arm's length.

**Strongest counterargument:** the token colour and the spoken line already carry the turn; bigger pips may crowd the top row.

**Cheapest disproof:** a 150% tour screenshot: if the pips touch the hint token, revert.

**Files:** `Assets/Scripts/Core/TurnPalette.cs` (add `PipSize(int textPercent)` and `PipSpacing(int textPercent)`), `Assets/Scripts/Unity/TreePlay.cs` (`TogetherRow` and `PaintTurn` use them with `TextScale.Percent`), `Tests/TurnPaletteTests.cs`.

**Rule:** size 9/11/13 px and spacing 12/14/16 px at 100/125/150%; anything below 125 uses the 100 values, 125–149 the 125 values, 150 and above the 150 values. Four pips' span (`3 × spacing + size`) stays ≤ 64 px (the 52 px token plus 6 px each side); spacing always exceeds size, so pips never touch.

**Acceptance (pure C#):** the three steps; in-between values; span ≤ 64 at every step; spacing > size.

**On screen:** at 150% the pips are 13 px. Not checked in a tour.

**Art/feel:** same filled and ring sprites, same seat inks; only size and spacing scale. No motion change.

## 5. The almanac says when a thing is in this garden (player-owned garden)

**Serves:** vision §2.4 "players own their garden", §3 truthful memory, charter §3.6 almanac.

**Player value:** the almanac spans every garden, so a found item may be in today's garden or only in an earlier one. Its keeper's line now adds "You chose it for this garden." when one of this garden's choices grew it, so the book connects to the place you are standing in. Nothing is added otherwise, so it can never be wrong.

**Strongest counterargument:** a nursery-bought copy of the item may also be in the garden and the line stays silent then.

**Cheapest disproof:** a stand-in reads three almanac entries and says which are in the current garden.

**Files:** `Assets/Scripts/Core/Almanac.cs` (add `KeeperLine(GardenItem item, WorldModel world)`), `Assets/Scripts/Unity/EvergroveApp.Journal.cs` (one call), `Tests/AlmanacHereTests.cs` (new).

**Rule:** the new overload returns `KeeperLine(item)`, plus " You chose it for this garden." when `world` is not null and some index `i` in `world.Choices` has `GardenCatalog.For(world.Garden, Math.Min(i, GardenCatalog.ChaptersPerGarden - 1), (VillageChoice)world.Choices[i]).Art == item.Art`. The old one-argument overload stays unchanged.

**Acceptance (pure C#):** a fresh world → the old line exactly; after a real `Choose`, the chosen item's line ends with the sentence and an unchosen item's doesn't; a null world → the old line; reading never changes the world (save text byte-identical before and after).

**On screen:** tapping or holding a found item in the almanac shows the extra sentence for items chosen in this garden. Not checked in a tour.

**Art/feel:** same toast; one short plain sentence in the keepers' voice.
