## 1. Does the axle's reach set the difficulty? (puzzle depth)

**Vision:** §2.2 "depth from a system… editorially reviewed difficulty curves". Run 1701 showed the axle pool can carry a smooth 12-board chapter, but a chapter drawn from solver work is a list of seeds, not a rule a designer or player can see. The axle joins two tiles A and B; how far apart they sit is visible on the board.

**Player value (future):** if a wider axle reliably means a firmer board, difficulty becomes something you can *see* ("the tied tiles are far apart today"), and an editor can shape a chapter by one visible dial instead of a hidden number.

**Counterargument:** work may not depend on distance at all; then the dial is a myth.

**Cheapest disproof:** group the qualifying seeds 0–239 by the Manhattan distance between A and B; if mean work does not rise with distance, distance is not a dial. Record either answer.

**Files:** `Assets/Scripts/Core/LinkedForkChapter.cs`; `Tests/LinkedForkChapterTests.cs`.

**Acceptance (pure C#):** new `LinkedForkChapter.WorkByReach(int seedLimit)` returns `int[][]`, one row `{distance, boards, totalWork}` per distance present, ascending by distance, over the same qualifying seeds `Draw` and `DrawByLevel` use; distance = |rowA − rowB| + |colA − colB| on the board's edge. Empty for a non-positive limit; deterministic. Tests: existing draws unchanged; rows sum to the qualifying count (197 for 240); locked rows for `WorkByReach(240)`; a recorded finding (rises / flat / mixed) in the class summary. Not wired; nothing visible.

**Art/feel:** none.

## 2. The preview names what your choice will hold (truthful village memory)

**Vision:** §3 "your choice changes the next puzzle, and the place remembers it truthfully". Before confirming a choice, the preview card shows the next stream's protected pipe and a generic rule line (`LocalizedVillage.EnvironmentalRule`). After confirming, tapping that same pipe says "This pipe is rooted in place by your quince tree from Bramble Run." The promise before and the memory after use different words.

**Player value:** the preview says, in the same words the board will use, what the choice will do: "This pipe is rooted in place by your quince tree from Bramble Run." The cause is understood before it is chosen.

**Counterargument:** a longer line in an already busy preview card.

**Cheapest disproof:** a stand-in player reads the preview and still can't say what the choice changes on the next board.

**Files:** `Assets/Scripts/Unity/EvergroveApp.ChoicePreview.cs` (the "Next stream preview rule" label only); new `Tests/PreviewCauseTests.cs`.

**Acceptance:** the label shows `LandmarkCause.For(choicePreview.WorldAfter)`, which already falls back to the generic rule outside English, for completed gardens and whenever the cause is unproven. Pure tests: for each of the three choices after solving stream 1 in Living mode (English), `LandmarkCause.Specific(preview.WorldAfter)` is non-empty and contains `GardenCatalog.For(world.Garden, 0, choice).Name`; the source world's choices and save JSON are unchanged by creating the preview; in PuzzleOnly mode `Specific` is "". On screen: open a choice card, read the line under the protected pipe.

**Art/feel:** words only, in the card's existing 16 pt line.

## 3. Undo says the turn came back (family play, one device)

**Vision:** §1a "any hand can help… undo and no penalty for wrong taps". Undo already hands the turn back to whoever made the move, and the token changes colour. A listening grandparent hears nothing different from an ordinary turn, so a child's undo is invisible to them.

**Player value:** after undo or redo while playing together, the token's spoken line says the turn came back: "Back to Honey, second of three." Everyone at the table, seeing or not, knows whose hand is next.

**Counterargument:** one more spoken variant to learn; an ordinary turn line may be enough.

**Cheapest disproof:** in a family session with VoiceOver, nobody notices the difference; then revert.

**Files:** `Assets/Scripts/Core/TakeTurns.cs`; `Assets/Scripts/Unity/TreePlay.Turns.cs`; `Tests/SpokenTurnTests.cs`.

**Acceptance (pure C#):** new `TakeTurns.SpokenBack(int turn, int players)`: together → "Back to {Name}, {ordinal} of {count}." using `TurnPalette.Name` and the same ordinal words as `Spoken`; alone → same as `Spoken` ("Playing alone."); never throws for negative or large turns, wraps like `Spoken`. Unity: `TurnToStep` marks the next `SpeakTurn` as a hand-back so it uses `SpokenBack`; any ordinary move or new board clears the mark. Nothing visible changes.

**Art/feel:** none visible; the words reuse the seat's paint name.

## 4. The protected tile is told by its frame for every eye (art and readability)

**Vision:** taste charter §1.3–1.4, §2.7 "readable and touchable". The protected tile's fill (`AnchoredTile` #F1DEB6, warm straw) is only about 1.13:1 against dry, wet and solved tiles. That is fine if the bark frame and badge carry the cue, but no test proves the frame stands out under colour-vision simulation, or that the straw fill still differs from the other tiles at all for every eye.

**Player value:** a player with any colour vision finds the protected pipe at a glance, by its frame first and its fill second.

**Counterargument:** the frame already passes 4.5:1 in normal vision; another gate may just restate it.

**Cheapest disproof:** run it; if every pair already passes, record that and change nothing.

**Files:** `Tests/ColourVisionTests.cs`; `Assets/Scripts/Unity/MosseloraTheme.cs` only if a finding needs a colour change.

**Acceptance (pure C#):** under Normal, Protanopia, Deuteranopia and Tritanopia: `LandmarkFrame` vs `AnchoredTile` ≥ 4.5:1 (`ColourVision.ContrastUnder`); `AnchoredTile` vs each of `DryTile`, `WetTile`, `SolvedTile` RGB distance ≥ 0.08 after simulation. Log the measured lowest values in a comment. If a check fails, adjust `AnchoredTile` toward a deeper straw only as far as needed, keeping `ThemeContrastTests` green (DryChannel and WetPipe 3:1 on it, frame 4.5:1). On screen: the protected tile in all four seasons (not checked by this run).

**Art/feel:** keep the warm straw family (a stretch of paper in sun); never a new hue.

## 5. A matching file says so (player-owned garden)

**Vision:** §2.4 "players own their garden". The restore card compares this phone's garden with the file's and warns when the file is smaller. When they match, a player sees two identical lines and must work out that restoring changes nothing, which is the moment people hesitate over a file they already saved.

**Player value:** "The file matches this phone's garden: same name, streams, things and days." The player can restore, or not, without fear.

**Counterargument:** matching summaries don't prove identical gardens (two gardens could share counts).

**Cheapest disproof:** the line is read as "identical" and someone loses a placement; the wording names only the four compared facts to prevent that.

**Files:** `Assets/Scripts/Core/GardenCompare.cs`; `Tests/GardenCompareTests.cs`.

**Acceptance (pure C#):** `GardenCompare.SameLine` constant with that exact text. `Lines` adds it as a third line only when both summaries have at least one stream and name (ordinal, trimmed), streams, things and days are all equal; the smaller warning and the same line never both appear; two fresh gardens still give two lines. On screen: Settings → restore a file copied a moment ago.

**Art/feel:** the card's existing line style.
