## 1. Mechanism (Unity 6000.3)

- **Advanced Text Generator (ATG)** is the HarfBuzz/ICU/FreeType text backend for UI Toolkit. It is opt-in in 6.3 and enabled project-wide via Edit > Project Settings > UI Toolkit > *Enable Advanced Text Generator*. Per-element, use `style.unityTextGenerator = new StyleEnum<TextGeneratorType>(TextGeneratorType.Advanced)` (USS: `-unity-text-generator: advanced`). The spike sets it per element and on the root, so it does not depend on the project checkbox.
  - https://docs.unity.com/en-us/engine/6000.3/manual/uitoolkits/uielements/uie-work-with-text/uie-advanced-text-generator/enable-and-use-atg
  - https://docs.unity.com/en-us/engine/6000.0/script-reference/unityengine/textgeneratortype/advanced
- **Limitations** (Unity docs): ATG supports dynamic font assets only; static font assets are not supported; glyph-metric customization is unavailable.
- **Direction**: `VisualElement.languageDirection` (`LanguageDirection.RTL`). Unity states RTL alone gives only basic reversal; line breaking and shaping require ATG enabled.
  - https://docs.unity.com/en-us/engine/6000.3/script-reference/unityengine/uielements/visualelement/languagedirection
- **uGUI cannot use ATG in 6.3.** Unity's 6.5 announcement says ATG becomes the default for UI Toolkit and that uGUI would get ATG only as an opt-in targeted at 6.8, possibly backported later. Current `Text` (uGUI) and TextMeshPro are therefore not an ATG path in this editor. The TextMeshPro claim is inferred from the sources reviewed, not separately verified.
  - https://discussions.unity.com/t/advanced-text-generator-atg-now-default-in-6-5/1715871
- **Platforms**: the sources reviewed do not list per-platform exclusions for ATG; iOS and Android support was **not verified** by this spike (only the macOS player was built).

Implication: migrating the player-facing dynamic text means moving those labels from uGUI to UI Toolkit. It cannot be done by flipping a uGUI setting.

## 2. What the spike does

- Left half: legacy uGUI `Text` with the locale font chosen by `LocaleFonts.Choose`.
- Right half: UI Toolkit `Label` with ATG, same string, `languageDirection` RTL for `ar`, `fa`, `he`.
- Strings: `title` and `first` keys from `Assets/Resources/Evergrove/Locales/{ar,fa,he,hi,bn,ta,th}.json`, read directly as TextAssets.
- Fonts: OS-installed only (`Font.CreateDynamicFontFromOSFont` via `LocaleFonts`). No font files added. The UI Toolkit side uses `FontDefinition.FromFont(<dynamic OS Font>)`, not a `FontAsset`. **Open question:** whether ATG accepts a legacy dynamic `Font` or requires a `FontAsset`. The screenshot would have answered this; it is unanswered.
- Screenshot: `ReadPixels` at end of frame, as in `DevScreenshot.cs`.

## 5. Screen-reader interaction

- The app already adds `UnityEngine.Accessibility` semantic nodes (`ScreenReaderBridge.cs`) for uGUI elements. The spike does **not** add or test accessibility nodes for UI Toolkit labels.
- A migration would need the same semantic labels and reading order on the UI Toolkit elements, plus on-device VoiceOver/TalkBack checks. Not tested here.

## 6. Font licensing

- The spike uses only OS fonts for the dev probe. It ships no font files.
- A shipping build still needs licensed, redistributable fonts for each enabled script (for example Noto-family fonts, which are commonly under the SIL Open Font License; **license terms not verified in this spike**). Each font must be converted to a dynamic font asset suitable for ATG and its license recorded.
- Font presence on a device is not a finished-language sign-off (already stated in `LocaleFonts`).

## 7. Migration plan and cost estimate (assumptions)

Assumptions: the player-facing text is generated from `EvergroveApp.cs` (uGUI `Text` in dozens of `Label`/`Button` helpers); one engineer; no redesign.

1. Move the shared `Label`/`Button` helpers to UI Toolkit behind a flag (about 1–2 weeks).
2. Add licensed dynamic fonts and per-script direction rules (about 1 week).
3. Re-create layout checks for compact and large text, plus screenshot tests at 320, 375, 768, 1024 and 1440 widths (about 1 week).
4. Screen-reader parity on iOS and Android (about 1–2 weeks).
5. Native-speaker and device review per enabled locale (calendar-dependent, not engineering-bounded).

Estimate: **4–7 engineering weeks** plus native review. The range is wide because the first step has not been screenshot-tested.

## 8. Recommendation: **partial (defer full migration)**

- Do **not** migrate the whole UI on this evidence. ATG is the right mechanism on paper, but the shaping result is unproven on this machine.
- Next step: rerun the spike on an unlocked, active macOS session (same command, same args), save the PNG to `docs/qa/text-spike-2026-11-23/`, and judge each column. Also test one iOS Simulator run.
- If ATG shows joining and conjuncts in the right column: partial migration of the dynamic puzzle prompt and `title` text to UI Toolkit, with RTL and Indic locales kept out of the release set until licensed fonts and native review pass.
- If it fails: keep uGUI, keep ar/fa/ur/he/Indic locales in the development channel only, and revisit at the uGUI ATG opt-in (Unity targets 6.8).

Still required: native-speaker review of every script, and a device check on iOS and Android.
