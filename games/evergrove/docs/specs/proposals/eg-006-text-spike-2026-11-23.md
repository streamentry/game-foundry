## 1. Mechanism (Unity 6000.3)

- **Advanced Text Generator (ATG)** is the HarfBuzz/ICU/FreeType text backend for UI Toolkit. It is opt-in in 6.3 and enabled project-wide via Edit > Project Settings > UI Toolkit > *Enable Advanced Text Generator*. Per-element, use `style.unityTextGenerator = new StyleEnum<TextGeneratorType>(TextGeneratorType.Advanced)` (USS: `-unity-text-generator: advanced`). The spike sets it per element and on the root, so it does not depend on the project checkbox.
  - https://docs.unity.com/en-us/engine/6000.3/manual/uitoolkits/uielements/uie-work-with-text/uie-advanced-text-generator/enable-and-use-atg
  - https://docs.unity.com/en-us/engine/6000.0/script-reference/unityengine/textgeneratortype/advanced
- **Limitations** (Unity docs): ATG supports dynamic font assets only; static font assets are not supported; glyph-metric customization is unavailable.
- **Direction**: `VisualElement.languageDirection` (`LanguageDirection.RTL`). Unity states RTL alone gives only basic reversal; line breaking and shaping require ATG enabled.
  - https://docs.unity.com/en-us/engine/6000.3/script-reference/unityengine/uielements/visualelement/languagedirection
- **uGUI cannot use ATG in 6.3.** Unity's 6.5 announcement says ATG becomes the default for UI Toolkit and that uGUI would get ATG only as an opt-in targeted at 6.8, possibly backported later. Current `Text` (uGUI) and TextMeshPro are therefore not an ATG path in this editor. The TextMeshPro claim is inferred from the sources reviewed, not separately verified.
  - https://discussions.unity.com/t/advanced-text-generator-atg-now-default-in-6-5/1715871
- **Platforms**: the sources reviewed do not list per-platform exclusions for ATG; iOS and Android support was **not verified** by this spike (only the macOS player was built).

Implication: migrating the player-facing dynamic text means moving those labels from uGUI to UI Toolkit. It cannot be done by flipping a uGUI setting.

## 2. What the spike does

- Left half: legacy uGUI `Text` with the locale font chosen by `LocaleFonts.Choose`.
- Right half: UI Toolkit `Label` with ATG, same string, `languageDirection` RTL for `ar`, `fa`, `he`.
- Strings: `title` and `first` keys from `Assets/Resources/Evergrove/Locales/{ar,fa,he,hi,bn,ta,th}.json`, read directly as TextAssets.
- Fonts: OS-installed only (`Font.CreateDynamicFontFromOSFont` via `LocaleFonts`). No font files added. The UI Toolkit side uses `FontDefinition.FromFont(<dynamic OS Font>)`, not a `FontAsset`. **Open question:** whether ATG accepts a legacy dynamic `Font` or requires a `FontAsset`. The screenshot would have answered this; it is unanswered.
- Screenshot: `ReadPixels` at end of frame, as in `DevScreenshot.cs`.

## 5. Screen-reader interaction

- The app already adds `UnityEngine.Accessibility` semantic nodes (`ScreenReaderBridge.cs`) for uGUI elements. The spike does **not** add or test accessibility nodes for UI Toolkit labels.
- A migration would need the same semantic labels and reading order on the UI Toolkit elements, plus on-device VoiceOver/TalkBack checks. Not tested here.

## 6. Font licensing

- The spike uses only OS fonts for the dev probe. It ships no font files.
- A shipping build still needs licensed, redistributable fonts for each enabled script (for example Noto-family fonts, which are commonly under the SIL Open Font License; **license terms not verified in this spike**). Each font must be converted to a dynamic font asset suitable for ATG and its license recorded.
- Font presence on a device is not a finished-language sign-off (already stated in `LocaleFonts`).

## 7. Migration plan and cost estimate (assumptions)

Assumptions: the player-facing text is generated from `EvergroveApp.cs` (uGUI `Text` in dozens of `Label`/`Button` helpers); one engineer; no redesign.

1. Move the shared `Label`/`Button` helpers to UI Toolkit behind a flag (about 1–2 weeks).
2. Add licensed dynamic fonts and per-script direction rules (about 1 week).
3. Re-create layout checks for compact and large text, plus screenshot tests at 320, 375, 768, 1024 and 1440 widths (about 1 week).
4. Screen-reader parity on iOS and Android (about 1–2 weeks).
5. Native-speaker and device review per enabled locale (calendar-dependent, not engineering-bounded).

Estimate: **4–7 engineering weeks** plus native review. The range is wide because the first step has not been screenshot-tested.

## 8. Recommendation: **partial (defer full migration)**

- Do **not** migrate the whole UI on this evidence. ATG is the right mechanism on paper, but the shaping result is unproven on this machine.
- Next step: rerun the spike on an unlocked, active macOS session (same command, same args), save the PNG to `docs/qa/text-spike-2026-11-23/`, and judge each column. Also test one iOS Simulator run.
- If ATG shows joining and conjuncts in the right column: partial migration of the dynamic puzzle prompt and `title` text to UI Toolkit, with RTL and Indic locales kept out of the release set until licensed fonts and native review pass.
- If it fails: keep uGUI, keep ar/fa/ur/he/Indic locales in the development channel only, and revisit at the uGUI ATG opt-in (Unity targets 6.8).

Still required: native-speaker review of every script, and a device check on iOS and Android.

## Addendum: iOS Simulator run (2026-11-23, lead)

The macOS session was inactive, so the probe was re-run on the iOS Simulator (iPhone 17 Pro, iOS 26.5, IL2CPP development build). The flag was passed as `SIMCTL_CHILD_mosseloraTextSpike`, using the new `DevArgs` environment fallback. Output: [`ios-simulator-text-spike.png`](../../qa/text-spike-2026-11-23/ios-simulator-text-spike.png). Observations by a non-native reader; **native review is required**:

| Script | Left column (legacy uGUI) | Right column (UI Toolkit, Advanced, `languageDirection=RTL`) |
| --- | --- | --- |
| Arabic `ar`, Persian `fa` | Letters appear joined, in right-to-left order | **Reversed.** The RTL flag reverses text that the generator already ordered. Latin "MOSSELORA" also renders as "AROLESSOM" |
| Hebrew `he` | **Reversed** (logical order drawn left-to-right) | Hebrew order looks correct, but the Latin text is reversed |
| Hindi `hi` | Conjuncts and vowel signs look attached | Same as left |
| Bengali `bn`, Tamil `ta`, Thai `th` | **Broken:** detached vowel signs with dotted circles | **Broken** in the same way |

The catalogs store logical-order Unicode with no Arabic presentation forms (checked), so the left-column Arabic result comes from the iOS text path, not from pre-shaped data.

**Revised reading:**
1. The spike's Advanced configuration is not yet correct. `languageDirection=RTL` behaves like a plain reversal, and it doesn't fix Bengali, Tamil or Thai. That suggests Advanced shaping was not actually active, or the OS-font font assets lack shaping support.
2. Legacy uGUI on iOS is not uniformly broken (Arabic, Persian and Hindi look acceptable), but Hebrew, Bengali, Tamil and Thai are.
3. Keep every complex-script locale out of shipping builds (the current allowlist is English only). The next spike step: enable Advanced text globally in PanelSettings/TextSettings, use font assets created from Noto (license-compatible, OFL) instead of OS fonts, drop the manual RTL flag, and re-capture.

## Iteration 2 (Noto, Advanced generator)

Run on the iOS Simulator (iPhone 17 Pro, iOS 26.5), IL2CPP development build, same spike. Capture: [`ios-simulator-text-spike-noto.png`](../../qa/text-spike-2026-11-23/ios-simulator-text-spike-noto.png). Verdicts below are by a non-native reader from the capture; **native review is still required**.

**Changes made in this iteration**
- Fonts: six OFL Noto Sans families (variable `wdth,wght` TTFs, default instance Regular) from the official Google Fonts source repository, under `games/evergrove/Assets/Resources/Dev/Noto/` with `SOURCES.md` and per-family OFL texts. The files are in `Resources/Dev`, not `Assets/Fonts/Noto`, because the runtime loader needs Resources. **Unity includes everything under Resources in every build, release included**, so about 2.5 MiB of font payload ships unless the spike and fonts are removed or moved behind a dev-only mechanism (decision needed).
- Both columns use the same Noto `Font`. The UI Toolkit column converts it with `FontAsset.CreateFontAsset(font, 40, 9, GlyphRenderMode.SDFAA, 2048, 2048, AtlasPopulationMode.Dynamic, true)` and `FontDefinition.FromSDFFont`.
- The Advanced Text Generator is set per element (`style.unityTextGenerator`) and on the root, as in iteration 1.
- The manual `languageDirection = RTL` reversal is removed. Latin "MOSSELORA" and the headers are no longer reversed in the right column.

**Font sizes** (Unity point sizes in the spike): labels 20 px, headers 18 px bold; FontAsset sampling size 40, atlas 2048x2048 dynamic.

**Per-script verdict (Noto, iteration 2)**

| Script | uGUI column (legacy) | UI Toolkit + ATG column | Verdict |
| --- | --- | --- | --- |
| Latin (`MOSSELORA`, headers) | Correct | Correct, no longer reversed | Pass |
| Arabic `ar` / Persian `fa` | Letters joined; word and character order looks wrong | Identical to the left column | **Fail:** joined, but the direction/order appears wrong; ATG shows no visible effect |
| Hebrew `he` | Letters drawn left to right (logical order) | Identical | **Fail:** direction appears wrong; ATG shows no visible effect |
| Devanagari `hi` | Conjuncts and vowel signs attached | Identical | Pass (visual, native review pending) |
| Bengali `bn` | Vowel sign ো detached after ল in "হলো" | Identical | **Fail:** detached vowel sign in both columns |
| Tamil `ta` | Marks placed; wraps to three lines | Identical | Pass (visual, native review pending) |
| Thai `th` | Marks stacked, no dotted circles seen in this sample | Identical | Pass (visual, native review pending; Thai word breaking not tested with long text) |

**What this run shows**
1. The two columns are visually identical for every script. With the generator enabled on the labels, the right column should differ from uGUI for at least the complex scripts. The identical output means the Advanced Text Generator is not visibly active in the labels on this build, or its shaping is not being applied. The earlier "Advanced" result was therefore not evidence of ATG shaping.
2. Removing the RTL flag fixed the Latin reversal, but Arabic and Hebrew order is still wrong in both columns, so the direction problem is not explained by the flag alone.
3. Bengali detached vowel signs persist with Noto fonts in both columns. This is the clearest signal that the shaping engine is not doing Indic shaping in either path.

**Not yet done:** the project-wide setting (Edit > Project Settings > UI Toolkit > Enable Advanced Text Generator) was not tried, because it changes a tracked ProjectSettings file that this spike must not commit. Verifying whether ATG engages on iOS (for example by a labelled before/after with a deliberately non-Latin probe, or Unity support confirmation) is the next step.

**Updated recommendation: still defer the full migration.** Do not migrate the uGUI UI to UI Toolkit on this evidence. The spike has not demonstrated correct shaping or bidi for Arabic, Persian, Hebrew or Bengali in any column. Keep ar, fa, he, ur and the Indic locales in the development channel only.

**Migration estimate (updated, same assumptions as the first estimate):** 4–7 engineering weeks plus native review, unchanged in size. Add about 1 week for the open ATG activation question and 1 week for the font-ship decision (Resources versus an AssetBundle or dev-only loader). The estimate stays conditional on the first failing step (ATG activation and Bengali/Arabic order), which must pass before any migration work starts.

**Font licence:** OFL 1.1 for all six families (texts in `Assets/Resources/Dev/Noto/`). Redistribution is permitted with the licence text. The files were renamed only on disk (the repo filename drops the brackets); their internal name tables were not edited. Reserved Font Name compliance was not checked beyond the OFL texts shipped alongside.

## Lead decision after iteration 2 (2026-11-23)

The Noto fonts and the iteration-2 `TextSpike.cs` changes are **not merged into main**. They stay on branch `worktree-agent-ab3626314e6ef3b6b` (commit `da32694`) for reference. Reasons:
1. The fonts were placed under `Assets/Resources/Dev/Noto/`. Unity ships every `Resources` folder in every build, so about 2.5 MiB would reach release builds. The BLD-007 audit just removed dev-only content from those builds.
2. The spike shows no measurable shaping benefit yet. The legacy and UI Toolkit columns render identically, Arabic and Hebrew word order still looks wrong, and Bengali still shows detached vowel signs.

**Next step for EG-006** (before any font ships): test the project-wide Advanced Text Generator setting in a throwaway worktree, and load fonts from a dev-only path that is excluded from release builds. Complex-script locales stay off the shipping allowlist (English only).
