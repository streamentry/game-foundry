# Vision ideas 20261128-1401

**Status:** proposal, not player-validated. Written by the unattended vision-ideas cycle. Every idea is small, deterministic and testable in pure C#. None adds timers, scores, network, data about children or new assets. Earlier runs (0855, 0927, 1001, 1101, 1201, 1301) were read first so nothing here repeats them. This run deliberately avoids a fifth colour-contrast pass and a fourth `ThingStory` sentence.

## 1. The axle's moment: aha or bookkeeping? (puzzle depth)

- **Vision:** §2.2 "depth from a system, not from content volume". The 1301 run found linked gates are the first rule whose reasoning jumps across the board, and asked whether the axle feels like "a real aha and not bookkeeping".
- **Idea:** measure *when* the axle matters. Run neighbour-only deduction (arc consistency, no link) until it stalls, record how many cells are already fixed, then apply one round of axle pruning and record whether it unlocks further neighbour progress. If the axle bites only at step 0 (before any neighbour reasoning) it is bookkeeping. If neighbour reasoning stalls part-way and the axle is what restarts it, it is an aha. Add `LinkedForks.AxleMoment(board)`. Still a hidden gate.
- **Player value (if it holds):** we can pick only boards where the axle is the turning point, the boards worth painting by hand.
- **Strongest counterargument:** every board in the set is ambiguous without the axle, so neighbour deduction must stall somewhere. The question is only how far it gets first, which might be "almost nowhere" on every board.
- **Cheapest disproof:** the measurement. If on most boards neighbour-only deduction fixes almost nothing before stalling, the axle is bookkeeping and the rule should not be built.
- **Files:** `Assets/Scripts/Core/LinkedForks.cs`, `Tests/LinkedForksTests.cs`.
- **Acceptance:** deterministic per seed; `AxleMoment` never removes the true orientation; for seeds 0–59 the test prints and locks: cells fixed before the stall (min / median / max), how many boards the axle restarts, and how many of those then finish with no guess ("aha boards"). Nothing on screen.
- **Art/feel:** none until it survives (the painted shaft from 1301 still stands).

## 2. The season says which stream brought it (truthful village memory)

> **Outcome: dropped.** The save counts nursery solves with streams and doesn't record when the story ended, so the line could name the wrong cause. See the [run log](../../vision-runs/20261128-1401.md).

- **Vision:** §4.2 "seasons arrive through the player's progress, never on a real-world timer"; §3 "the place remembers it truthfully". After the story, a season turns every few streams and a neighbour leaves a note with a tale, but nothing says *why* it turned, so it can read like a calendar.
- **Idea:** the season note ends with its true cause: "Autumn came with stream 19." Pure `GardenSeason.TurnedBy(puzzlesSolved)` and `GardenSeason.CauseLine(world)`, appended to the note body in `NoteSeasonTurn`. Only after the story (when the turn is purely stream-driven) and only in Living mode; otherwise "".
- **Player value:** the garden visibly answers the player's own work ("we did that"), and a family can say "the snow came when we finished that one".
- **Counterargument:** one more sentence in a letter; seasons may be nicer as a gentle mystery.
- **Cheapest disproof:** in M3, ask players what made autumn arrive. If they already say "I finished more streams", drop the line.
- **Files:** `Assets/Scripts/Core/GardenSeason.cs`, `Assets/Scripts/Unity/EvergroveApp.GardenNotes.cs`, new `Tests/SeasonCauseTests.cs`.
- **Acceptance:** pure tests: the turning stream is the smallest solve count with the current season; it agrees with `AfterStory` for every count 0–200; "" during the story, in Puzzle-only modes, for a null world, and before the first turn after the story; the season word matches `GardenSeason.For(world)`. On screen: the next season letter after the story ends with the line.
- **Art/feel:** the existing letter, unchanged.

## 3. Someone joins without resetting the turn (family play, one device)

- **Vision:** §1a "any hand can help"; §4.4 rung 0. Today, tapping the take-turns token to add a seat mid-board (a grandchild arrives) sends the turn back to the first player and forgets the turn history, so undo no longer hands the turn back correctly.
- **Idea:** `TakeTurns.TurnAfterResize(turn, players)`: alone → 0; the current turn is kept when it still exists at the new table, otherwise 0. The ledger records the new turn at the current step instead of being cleared.
- **Player value:** the person whose turn it was keeps it when someone sits down; nobody's move is skipped or repeated.
- **Counterargument:** joining mid-board is rare; most families set the table first.
- **Cheapest disproof:** family co-play session: count mid-board joins. If none happen in 5 groups, the change is harmless but unneeded.
- **Files:** `Assets/Scripts/Core/TakeTurns.cs`, `Assets/Scripts/Unity/TreePlay.cs` (one line, same line count), `Assets/Scripts/Unity/TreePlay.Turns.cs`, new `Tests/JoinTableTests.cs`.
- **Acceptance:** pure tests over every turn × players pair, negatives and values above four (never throws, always in range); a source check that `ToggleTogether` no longer sets `turn = 0` and `TreePlay.cs` did not grow.

## 4. The turn token eases to the next colour (art and feel)

- **Vision:** taste charter rules 1 and 3: calm, and the world explains itself through motion before words. The token's colour snaps on every hand-off.
- **Idea:** the disc's colour eases from the old turn colour to the new over 0.18 s (smoothstep). With reduced motion it changes instantly, as now. Pure `TurnPalette.Blend(from, to, t)` and `TurnPalette.FadeSeconds`.
- **Player value:** a hand-off reads as a gentle pass rather than a flicker, and the eye is drawn to the token as it changes.
- **Counterargument:** a snap is more noticeable than a fade; a fade could be missed by someone not looking.
- **Cheapest disproof:** side-by-side capture for the art review; if the fade reads as lag, revert to the snap.
- **Files:** `Assets/Scripts/Core/TurnPalette.cs`, `Assets/Scripts/Unity/TreePlay.cs` (one line, same count), `Assets/Scripts/Unity/TreePlay.Turns.cs`, `Tests/TurnPaletteTests.cs`.
- **Acceptance:** `Blend` returns exactly `from` at t ≤ 0 and `to` at t ≥ 1, is monotonic per channel, never leaves 0–1; reduced motion paints the target immediately (source check). One running fade at a time.
- **Art/feel:** the four existing turn colours; no new hue. Smoothstep, 0.18 s, unscaled time.

## 5. Holding a water tile says which way it opens (accessibility)

- **Vision:** §2.7 readable for the people we design for; M5 gate. Screen-reader users hear "Opens up and right" (1001), but a sighted low-vision player who long-presses a stream tile only sees "Turn this tile".
- **Idea:** the long-press caption on a stream tile adds the openings in English: "Turn this tile. Opens up and right." Anchored tiles: "This tile stays where it is. Opens left and down." Pure `TileOpenings.Caption(anchored, kind, rotation)`. Other languages keep today's caption.
- **Player value:** at 150% text, someone who can't make out a thin pipe end can check a tile by holding it, without a screen reader.
- **Counterargument:** the pipe art already shows the openings; more words on the board.
- **Cheapest disproof:** in M3 with 65+ players, see whether anyone long-presses tiles at all.
- **Files:** `Assets/Scripts/Core/TileOpenings.cs`, `Assets/Scripts/Unity/EvergroveApp.Puzzle.cs`, `Tests/TileOpeningsTests.cs`.
- **Acceptance:** pure tests for every kind × rotation, both anchored states, out-of-range rotation (falls back to the bare caption, never throws). On screen: long-press a tile in English portrait and landscape at 150% text.
- **Art/feel:** the existing long-press caption style.
