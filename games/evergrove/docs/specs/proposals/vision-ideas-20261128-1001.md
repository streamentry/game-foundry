## 1. Do root stones need real reasoning? (puzzle depth)

- **Vision:** §2.2 "depth from a system, not content volume" (unsolved). Run 0927 found that local deduction alone forces every tile on every authored board. Its next step: measure root-stone boards (`RootedBoards`, run 0855) the same way, and count the guesses a board needs once deduction stalls.
- **Player value (later):** if root stones make boards that need a step of lookahead, the depth proposal's C1 mechanic earns its painted tile. If not, we know before any art is drawn.
- **Strongest counterargument:** another hidden number; and solver guesses are a proxy for human difficulty, not a measure of it.
- **Cheapest disproof:** if root-stone boards are also fully forced by local deduction (zero guesses for nearly all seeds), C1 adds shape but not reasoning, and depth must come from elsewhere (ecology constraints).
- **Files:** new `Assets/Scripts/Core/RootedDepth.cs` (+ `.meta`); new `Tests/RootedDepthTests.cs`.
- **Acceptance (pure C#):** for 200 seeds × 1 and 2 roots: arc-consistency forced count and a deduce-then-guess search's guess count are deterministic; deduction never removes the true orientation; the guessing search finds exactly the generated solution; forced ≤ pipe cells. The distribution (boards needing 0, 1, 2+ guesses) goes in the run log.
- **On screen:** nothing.

## 2. Changing your mind leaves no ghosts (truthful village memory)

- **Vision:** §3 "the place remembers it truthfully"; charter rule 5. Two recent lines read the latest choice from the save: the protected-pipe cause (`LandmarkCause`) and the lantern letter (`DayRhythm.LanternWords`). A player can reconsider their latest choice (`WorldModel.ReconsiderLatestChoice`). Nothing tests that the village then stops talking about the thing that no longer exists.
- **Player value:** after a player swaps the quince for the footbridge, no neighbour, letter or pipe mentions the quince again.
- **Strongest counterargument:** test-only work; nothing new appears.
- **Cheapest disproof:** if the audit finds no stale line, it ships as a guard and costs nothing more.
- **Files:** new `Tests/ReconsiderTruthTests.cs`; a fix in the Core file that leaks, only if one does.
- **Acceptance:** for each of the three families as the first choice and each other family as its replacement: after `ReconsiderLatestChoice` and the new `Choose`, `LandmarkCause`, `LanternWords`, `Memory`, `Consequence` and `Journal` never name the replaced item, and name the new one wherever they named the old.

## 3. Undo hands the turn back (family play, one device)

- **Vision:** §1a "any hand can help", "no penalty for wrong taps"; §4.4 rung 0. With take-turns on, every move passes the turn, but undo doesn't pass it back. If a grandchild's slip is undone, the grandchild's turn is gone and the next person plays twice.
- **Player value:** undo puts the board *and* the turn back where they were, so a slip costs nobody their turn. Redo moves it forward again.
- **Strongest counterargument:** families may undo rarely, or may prefer to just carry on.
- **Cheapest disproof:** in the family co-play session, count undos during take-turns play; if no group undoes, the change is harmless but unproven.
- **Files:** `Core/TakeTurns.cs` (`Previous`); `Unity/TreePlay.Turns.cs` (turn back/forward); `Unity/BoardKit.cs` (`UndoRow` tells its board's `TreePlay`); new `Tests/TurnBackTests.cs`.
- **Acceptance:** `Previous(Next(t, p), p) == t` for every t and p in 1..4; alone always 0; out-of-range input never throws. In Unity, a successful undo moves the turn back one and a successful redo moves it forward one, on every board kind that uses the shared undo row; a refused undo changes nothing; alone, nothing changes.
- **Art/feel:** the token's colour and pips simply step back, with the same paint as a forward turn.

## 4. The palette proves its own contrast (art and readability)

- **Vision:** §2.7 "readable and touchable"; charter rule 4, "large readable type is standard". `MosseloraTheme` cites contrast ratios in comments, but nothing checks them, and a later colour tweak could silently drop text below WCAG.
- **Player value:** every ink-on-paper pairing the game uses stays readable for 40+ eyes, and a future tweak that breaks it fails the build.
- **Strongest counterargument:** the palette already passed a painted-UI audit (2026-11-23).
- **Cheapest disproof:** if every pair already passes, the test is just a lock; that's still worth having.
- **Files:** new `Core/ThemeColours.cs` (+ `.meta`, hex strings as the one source); `Unity/MosseloraTheme.cs` (reads those strings); new `Tests/ThemeContrastTests.cs`.
- **Acceptance:** body text (Ink, SecondaryInk) on Paper, CardFill, Sand, SagePanel, LeafSoft and RiverWash ≥ 4.5:1; white on ForestAction, WaterAction and EarthAction ≥ 4.5:1; DryChannel and WaterChannel on DryTile, WetTile, SolvedTile, AnchoredTile and HintFocusTile ≥ 3:1; LandmarkFrame on AnchoredTile ≥ 4.5:1. `MosseloraTheme` has no hex literal of its own. No colour changes unless a pair fails, and then only the smallest lightness change in the same hue.

## 5. The garden file says what it is (player-owned garden)

- **Vision:** §2.4 "players own their garden". The copied garden file is a block of JSON. Pasted into Notes or an email to oneself, nothing says what it is or that all of it must be kept.
- **Player value:** the copied text starts with one plain line: "Mosselora garden file: Willowbank, 7 streams restored. Keep all of this text to bring the garden back." Restoring still works with or without that line.
- **Strongest counterargument:** few players will open the clipboard text.
- **Cheapest disproof:** in a restore walkthrough, ask the player where they'd keep the file and whether they know what the pasted text is.
- **Files:** `Core/GardenTransfer.cs` (new `ExportForPeople`, tolerant `TryImport`); `Unity/EvergroveApp.GardenFile.cs` (the copy uses `ExportForPeople`); new `Tests/GardenFileHeaderTests.cs`.
- **Acceptance:** `Export` is byte-for-byte unchanged; `ExportForPeople` = header line + newline + `Export`; `TryImport` accepts both, and accepts leading text only when it contains no `{` and is at most 300 characters; anything else keeps today's errors; the header uses only save fields (garden name, streams restored) and says "1 stream" in the singular.
